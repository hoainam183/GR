\section{Mở đầu chương}
Chương này trình bày chi tiết quá trình triển khai Phase 1 của hệ thống RAG v2: thu thập dữ liệu, làm sạch dữ liệu, và xây dựng pipeline chunking. Đây là giai đoạn nền tảng, quyết định chất lượng của toàn bộ hệ thống retrieval ở các phase sau.

Các nội dung triển khai bao gồm:
\begin{itemize}
    \item Thu thập và làm sạch dữ liệu từ 3 nguồn (quydinh, ctdt, stsv);
    \item Xử lý PDF với nhiều công cụ (Docling, PyMuPDF4LLM, olmOCR);
    \item Triển khai chi tiết 4 loại chunker chuyên biệt;
    \item Làm giàu metadata tự động cho chunks CTDT.
\end{itemize}

\section{Thu thập và xử lý dữ liệu quy định (quydinh)}

\subsection{Xử lý PDF với olmOCR}

\subsubsection{Vấn đề font encoding}
Nhiều văn bản PDF quy chế có lỗi font, khi extract text sẽ cho ra ký tự sai:
\begin{verbatim}

\subsection{Thuật toán chunking}
\begin{verbatim}
def chunk_document(self, content, source_file):
    # 1. Trích xuất metadata văn bản (căn cứ, ngày ban hành)
    doc_metadata = self._extract_doc_metadata(content)
    
    # 2. Tạo header chunk
    header = self._extract_header(content)
    
    # 3. Chia theo Chương
    chapters = self._split_by_chapters(content)
    
    # 4. Trong mỗi Chương: chia theo Điều
    for chapter in chapters:
        articles = self._split_by_articles(chapter)
        
        for article in articles:
            # 5. Tạo parent chunk (toàn bộ Điều)
            parent = self._create_parent_chunk(article, chapter)
            
            # 6. Tạo child chunks (từng Khoản)
            children = self._create_child_chunks(article, parent)
    
    # 7. Xử lý phụ lục
    appendix = self._extract_appendix(content)
    
    return chunks, stats
\end{verbatim}

\subsection{Readable ID Format}
Mỗi chunk được gán readable ID phản ánh vị trí trong cấu trúc pháp lý:
\begin{verbatim}
def _generate_readable_id(self, chapter, article, clause):
    # c1_d5_k2 = Chương 1, Điều 5, Khoản 2
    parts = []
    if chapter: parts.append(f"c{chapter}")
    if article: parts.append(f"d{article}")
    if clause:  parts.append(f"k{clause}")
    return "_".join(parts)
    
# Ví dụ: c1_d5_k2 → Chương I, Điều 5, Khoản 2
# Ví dụ: c3_d18   → Chương III, Điều 18 (parent, toàn bộ điều)
# Ví dụ: header   → Phần header văn bản
\end{verbatim}

\section{Triển khai RecursiveChunker}

\subsection{Chiến lược H2 Section-based}
RecursiveChunker tách document theo H2 section boundaries:

\begin{verbatim}
def chunk_document(self, text, source=None):
    # 1. Trích xuất tiêu đề document
    doc_title = self._extract_document_title(text)
    
    # 2. Trích xuất tất cả headings
    headings = self._extract_section_headings(text)
    
    # 3. Trích xuất các section H2
    h2_sections = self._extract_h2_sections(text)
    
    # 4. Xử lý phần preamble (trước H2 đầu tiên)
    preamble = text[:h2_sections[0]['start_pos']]
    
    all_chunks = []
    for section in h2_sections:
        # 5. Parent chunk = toàn bộ section H2
        parent = self._create_parent_from_section(section)
        
        # 6. Child chunks = tách section bằng TextSplitter
        children = self._split_text_to_chunks(
            section['content'], doc_title, headings, source
        )
        
        all_chunks.extend([parent] + children)
    
    return all_chunks, stats
\end{verbatim}

\section{Triển khai STSVChunker}

\subsection{Phân loại nội dung tự động}
STSVChunker phân tích nội dung Description và chọn chiến lược phù hợp:

\begin{verbatim}
def _segment(self, description, title, type_doc):
    # Loại 1: Ngắn (< 1500 chars) -> 1 chunk
    if len(description) <= SINGLE_CHUNK_THRESHOLD:
        return [(description, None, None)]
    
    # Loại 2: Có phần Roman (I., II., III.)
    if _RE_ROMAN.search(description):
        return self._split_by_roman_then_items(description)
    
    # Loại 3: Có mục số (1., 2., ...)
    if _RE_NUMBERED.search(description):
        return self._split_by_numbered_items(description)
    
    # Loại 4: Văn xuôi thuần
    return [(description, None, None)]
\end{verbatim}

\subsection{Sequential tracking cho mục số}
Để tránh nhầm lẫn sub-items (ví dụ ``1. Miễn học phần...'' xuất hiện trong mục 8) với mục cấp cao, STSVChunker sử dụng sequential tracking:
\begin{verbatim}
# Chỉ nhận mục mới khi số thứ tự đúng = expected
# 1 -> 2 -> 3 -> ... (tuần tự)
expected_num = None
for line in lines:
    m = re.match(r'^(\d{1,2})\.\s+\S', stripped)
    if m:
        num = int(m.group(1))
        if expected_num is None and num == 1:
            expected_num = 1
        if expected_num is not None and num == expected_num:
            # Đây là mục cấp cao mới
            expected_num = num + 1
\end{verbatim}

\subsection{Context prefix cho retrieval}
Mỗi chunk được thêm prefix để đảm bảo context khi retrieval:
\begin{verbatim}
def _build_content(self, text, title, type_doc, section_ctx):
    # Prefix: [Title | TypeDoc | Section_context]
    parts = [title]
    if type_doc:     parts.append(type_doc)
    if section_ctx:  parts.append(section_ctx)
    prefix = " | ".join(parts)
    return f"[{prefix}]\n{text}"

# Ví dụ output:

# 2. Chọn mục "Đăng ký học phần"
\end{verbatim}

\section{Triển khai Embedding Layer}

Embedding Layer chịu trách nhiệm chuyển đổi văn bản (query và document) thành vector số trong không gian 1024 chiều, phục vụ cho tìm kiếm ngữ nghĩa trong Qdrant.

\subsection{Kiến trúc Clean Architecture}

Toàn bộ module embedding được thiết kế theo mẫu Abstract Base Class + Factory Pattern:

\begin{verbatim}
# embedding/base.py — Abstract Base Class
class BaseEmbedder(ABC):
    @property
    @abstractmethod
    def dimension(self) -> int: ...

    @abstractmethod
    def embed(self, texts: List[str]) -> List[List[float]]: ...

    @abstractmethod
    def embed_query(self, text: str) -> List[float]: ...

    @abstractmethod
    def embed_documents(self, texts: List[str]) -> List[List[float]]: ...
\end{verbatim}

Factory function cho phép đổi provider qua biến môi trường \texttt{EMBEDDING\_PROVIDER}:
\begin{verbatim}
# embedding/__init__.py — Factory Pattern
def create_embedder(settings) -> BaseEmbedder:
    provider = settings.embedding_provider  # "bge_m3"|"e5"|"ensemble"
    if provider == "bge_m3":
        return BGEm3Embedder()
    if provider == "e5":
        return E5MultilingualEmbedder()
    if provider == "ensemble":
        return EnsembleEmbedder([BGEm3Embedder(), E5MultilingualEmbedder()])
\end{verbatim}

\subsection{BGE-M3 Embedder}
\textbf{File:} \texttt{embedding/bge\_m3.py} (140 dòng, 4.547 bytes)

BGEm3Embedder là wrapper cho mô hình \texttt{BAAI/bge-m3} qua thư viện FlagEmbedding:
\begin{verbatim}
class BGEm3Embedder(BaseEmbedder):
    DEFAULT_MODEL = "BAAI/bge-m3"

    def __init__(self, model_name=DEFAULT_MODEL, use_fp16=True,
                 device=None, batch_size=32, max_length=512):
        if device is None:
            device = "cuda" if torch.cuda.is_available() else "cpu"
        if device == "cpu":
            use_fp16 = False

        self._model = BGEM3FlagModel(
            model_name, use_fp16=use_fp16, device=device
        )
        self._dimension = 1024
\end{verbatim}

\textbf{Ba chế độ encoding:}
\begin{itemize}
    \item \textbf{Dense encoding} (\texttt{embed()}, \texttt{embed\_query()}): Trả về vector 1024 chiều cho tìm kiếm ngữ nghĩa;
    \item \textbf{Sparse encoding} (\texttt{encode\_sparse()}): Trả về token-weight dict cho keyword-level matching;
    \item \textbf{Encode all} (\texttt{encode\_all()}): Trả về cả dense và sparse trong một lần gọi.
\end{itemize}

\subsection{E5 Multilingual Embedder}
\textbf{File:} \texttt{embedding/e5\_multilingual.py} (91 dòng, 2.965 bytes)

E5MultilingualEmbedder sử dụng \texttt{sentence-transformers} cho mô hình \texttt{intfloat/multilingual-e5-large}:
\begin{verbatim}
class E5MultilingualEmbedder(BaseEmbedder):
    DEFAULT_MODEL = "intfloat/multilingual-e5-large"
    QUERY_PREFIX = "query: "
    PASSAGE_PREFIX = "passage: "

    def __init__(self, model_name=DEFAULT_MODEL, device=None,
                 batch_size=32, max_length=512):
        self._model = SentenceTransformer(
            model_name, device=device,
            model_kwargs={"low_cpu_mem_usage": True,
                          "dtype": torch.float16}
        )
        self._model.max_seq_length = max_length
\end{verbatim}

\textbf{Đặc điểm quan trọng:}
\begin{itemize}
    \item \textbf{Prefix tự động}: \texttt{embed\_query()} tự thêm \texttt{"query: "}, \texttt{embed\_documents()} tự thêm \texttt{"passage: "} — đúng theo yêu cầu của E5;
    \item \textbf{Normalize embeddings}: Output được L2-normalize, cho phép dùng cosine similarity trực tiếp;
    \item \textbf{FP16} để giảm bộ nhớ GPU khi inference.
\end{itemize}

\subsection{Ensemble Embedder}

EnsembleEmbedder kết hợp nhiều embedders (mặc định BGE-M3 + E5) nhưng trong thực tế, pipeline lưu trữ và tìm kiếm vector của từng mô hình riêng biệt trên Qdrant (named vectors), không tính weighted average.

\textbf{Quyết định thiết kế:}
\begin{itemize}
    \item Mỗi mô hình sinh vector độc lập, lưu vào named vector riêng trong Qdrant collection;
    \item Khi search, Qdrant tìm kiếm trên cả hai named vectors (\texttt{bge\_m3} và \texttt{e5}), sau đó kết hợp kết quả;
    \item Thiết kế này cho phép linh hoạt: có thể thêm/bớt embedding model mà không cần re-index toàn bộ.
\end{itemize}

\section{Triển khai Hybrid Retrieval}

Hybrid Retrieval kết hợp vector search (Qdrant) và keyword search (Elasticsearch) qua Reciprocal Rank Fusion, sau đó mở rộng lên multi-collection search song song.

\begin{verbatim}
class HybridSearch:
    def __init__(self, qdrant_store, es_store,
                 vector_weight=0.8, keyword_weight=0.2):
        self._qdrant = qdrant_store
        self._es = es_store

    def search(self, query, bge_m3_query, e5_query,
               top_k=20, vector_pool_k=15, keyword_pool_k=15):
        # 1. Vector search → top vector_pool_k
        vector_results = self._qdrant.search(
            bge_m3_query, e5_query, top_k=vector_pool_k
        )
        # 2. Keyword search → top keyword_pool_k
        keyword_results = self._es.keyword_search(
            query, top_k=keyword_pool_k
        )
        # 3. RRF fusion kết hợp 2 danh sách
        fused = self._rrf_fusion(
            vector_results, keyword_results,
            self.vector_weight, self.keyword_weight
        )
        return fused[:top_k]
\end{verbatim}

\textbf{Thuật toán RRF (Reciprocal Rank Fusion):}
\begin{verbatim}
def _rrf_fusion(self, vector_results, keyword_results,
                vector_weight, keyword_weight, k=60):
    scores = {}  # doc_id -> fused_score
    for rank, doc in enumerate(vector_results):
        scores[doc.id] = vector_weight / (k + rank + 1)
    for rank, doc in enumerate(keyword_results):
        scores[doc.id] += keyword_weight / (k + rank + 1)
    return sorted(scores, key=scores.get, reverse=True)
\end{verbatim}

\textbf{Ưu điểm RRF:} Không cần normalize điểm số từ 2 hệ thống có thang điểm khác nhau (cosine similarity vs BM25 score).

@register_reranker("bge")
class BGEReranker(BaseReranker):
    def __init__(self, model_name="BAAI/bge-reranker-v2-m3",
                 device=None, use_fp16=None,
                 batch_size=32, top_k=5, score_threshold=0.0):
        self._model = FlagReranker(
            model_name, device=device, use_fp16=use_fp16
        )

    def rerank(self, query, documents, top_k=None,
               score_threshold=None) -> List[Dict]:
        # 1. Build (query, doc_text) pairs
        pairs = [[query, doc["text"]] for doc in documents]

        # 2. Compute relevance scores
        scores = self._model.compute_score(
            pairs, batch_size=self.batch_size
        )

        # 3. Attach rerank_score, sort descending
        scored_docs = [{**doc, "rerank_score": float(score)}
                       for doc, score in zip(documents, scores)]
        scored_docs.sort(key=lambda d: d["rerank_score"],
                         reverse=True)

        # 4. Top-K + score threshold filter
        return scored_docs[:top_k]
\end{verbatim}

def rag_flow(question, history, reflector, bge_embedder,
             e5_embedder, searcher, reranker, chat_model,
             self_evaluator, tavily_tool, cfg) -> Dict:
    # 1. Reflection: rewrite query cho retrieval tốt hơn
    search_query = reflector.reflect(question, chat_history)

    # 2. Embed: tạo vector cho cả BGE-M3 và E5
    bge_vec = bge_embedder.embed_query(search_query)
    e5_vec = e5_embedder.embed_query(search_query)

    # 3. Hybrid Search: Qdrant + Elasticsearch + RRF fusion
    raw_results = searcher.search(
        query=search_query,
        bge_m3_query=bge_vec, e5_query=e5_vec,
        top_k=cfg["top_k"] * 4,  # Pool 4x để reranker chọn
    )

    # 4. Rerank: chọn top-K tài liệu chính xác nhất
    reranked = reranker.rerank(
        query=search_query, documents=raw_results,
        top_k=cfg["top_k"]   # Mặc định: 5
    )

    # 5. Generate: LLM sinh câu trả lời từ context
    context = _format_context(reranked)
    answer = chat_model.generate(
        query=question, context=context, mode="rag"
    )

    # 6. Self-eval: kiểm tra chất lượng
    eval_result = self_evaluator.evaluate(
        query=question, context=context, response=answer
    )
    if not eval_result["pass"]:
        # 7. Tavily fallback: tìm web, sinh lại
        answer = _tavily_fallback(question, tavily_tool,
                                  chat_model, history)

    return {"answer": answer, "sources": reranked, ...}
\end{verbatim}

    web_context = search_result["context"]

\textbf{POST /chat/stream} -- Server-Sent Events (SSE):
\begin{verbatim}
@router.post("/chat/stream")
async def chat_stream(request, body) -> StreamingResponse:
    async def event_generator():
        # Gửi session_id như SSE event đầu tiên
        yield f'data: {{"session_id": "{session_id}"}}\n\n'

        # Producer-consumer pattern với asyncio.Queue
        queue = asyncio.Queue()

        def _produce():
            for chunk in pipeline.query_stream(...):
                loop.call_soon_threadsafe(
                    queue.put_nowait, chunk)
            loop.call_soon_threadsafe(
                queue.put_nowait, None)  # sentinel

        loop.run_in_executor(None, _produce)

        while True:
            chunk = await queue.get()
            if chunk is None:
                yield "data: [DONE]\n\n"
                break
            yield f"data: {chunk}\n\n"

    return StreamingResponse(
        event_generator(),
        media_type="text/event-stream"
    )
\end{verbatim}

\textbf{Quyết định thiết kế SSE streaming:}
\begin{itemize}
    \item \textbf{Producer-consumer với asyncio.Queue}: Pipeline chạy synchronous trong thread pool (producer), SSE event loop đọc từ queue (consumer) -- bridge giữa sync và async;
    \item \textbf{Session ID gửi trước}: Frontend nhận session\_id ngay lập tức, không cần đợi câu trả lời;
    \item \textbf{Sentinel \texttt{[DONE]}}: Chuẩn SSE signaling, frontend biết stream đã kết thúc.
\end{itemize}

\section{Hệ thống Đánh giá (Evaluation Pipeline)}

Để đảm bảo chất lượng hệ thống RAG, một quy trình đánh giá toàn diện đã được thiết lập, kết hợp giữa các chỉ số retrieval truyền thống và các chỉ số LLM-based hiện đại.

\subsection{Chỉ số Đánh giá Retrieval}
Sử dụng các chỉ số chuẩn để đo lường khả năng tìm kiếm đúng tài liệu:
\begin{itemize}
    \item \textbf{Hit Rate@K}: Tỉ lệ câu hỏi có ít nhất một tài liệu liên quan nằm trong top K kết quả trả về;
    \item \textbf{MRR (Mean Reciprocal Rank)}: Đo lường vị trí của tài liệu đúng đầu tiên. MRR càng cao nghĩa là tài liệu đúng càng nằm ở top đầu;
    \item \textbf{Precision@K và Recall@K}: Độ chính xác và độ bao phủ của tập kết quả.
\end{itemize}

\subsection{Chỉ số Ragas cho Generation}
Sử dụng khung đánh giá Ragas để đo lường chất lượng câu trả lời của LLM:
\begin{itemize}
    \item \textbf{Faithfulness (Tính trung thực)}: Câu trả lời có hoàn toàn dựa trên context được cung cấp không? (phát hiện ảo giác - hallucination);
    \item \textbf{Answer Relevance (Độ liên quan)}: Câu trả lời có giải quyết đúng vấn đề người dùng hỏi không?;
    \item \textbf{Context Precision \& Recall}: Đo lường chất lượng của các đoạn văn bản được chọn làm context.
\end{itemize}

\subsection{Quy trình Đánh giá Offline}
\textbf{File:} \texttt{evaluation/evaluate_phase3.py}

Hệ thống chạy đánh giá tự động trên bộ dữ liệu kiểm thử (Golden Dataset):
\begin{enumerate}
    \item Đọc tập hợp các cặp (Câu hỏi, Tài liệu liên quan, Câu trả lời mong đợi);
    \item Chạy pipeline RAG để lấy kết quả thực tế;
    \item Sử dụng Gemini làm "Judge" để chấm điểm dựa trên các tiêu chí Ragas;
    \item Xuất báo cáo tổng hợp (Summary Report) dưới dạng CSV để theo dõi sự cải thiện qua từng phiên bản code.
\end{enumerate}

\section{Kết luận chương}
Chương này đã trình bày chi tiết quá trình triển khai toàn bộ hệ thống RAG v2 qua 8 module chính:

\begin{itemize}
    \item \textbf{Thu thập và xử lý dữ liệu}: 137 tài liệu từ 3 nguồn; 4 loại chunker chuyên biệt tạo ra 2.752 chunks chất lượng cao; Metadata Enrichment tự động trích xuất thời điểm hiệu lực, khóa áp dụng chuẩn hóa (\texttt{applicable\_cohort});
    
    \item \textbf{Kiến trúc Agent ReAct}: LangGraph-based agent với các luồng Planner-Executor xử lý so sánh đa nguồn; Cơ chế phân rã câu hỏi (Decomposition) và quản lý Context Window thông minh;
    
    \item \textbf{Tầng Caching \& Performance}: Redis Caching 2 cấp độ (pre/post-retrieval) giúp tiết kiệm 70-90\% latency cho các câu hỏi lặp lại; Hệ thống Invalidation theo tag đảm bảo dữ liệu luôn mới;
    
    \item \textbf{Embedding \& Retrieval}: Dual embedding (BGE-M3 + E5); Hybrid Retrieval (Vector + Keyword) kết hợp qua RRF fusion; Multi-Collection Search song song;
    
    \item \textbf{Reranking \& Generation}: Cross-encoder reranker tối ưu relevance; Gemini 2.5 Flash sinh câu trả lời có trích dẫn nguồn chi tiết;
    
    \item \textbf{Hệ thống Đánh giá}: Quy trình đánh giá tự động với Ragas metrics, đo lường Faithfulness và Answer Relevance để kiểm soát chất lượng đầu ra;
    
    \item \textbf{Hạ tầng Backend}: FastAPI server hỗ trợ SSE streaming; MongoDB Memory lưu trữ lịch sử chat và provenance đầy đủ; Centralized configuration qua Pydantic BaseSettings.
\end{itemize}

Kết quả, hệ thống sẵn sàng nhận request từ frontend, xử lý qua toàn bộ pipeline (Router $\rightarrow$ Reflection $\rightarrow$ Embed $\rightarrow$ Search $\rightarrow$ Rerank $\rightarrow$ Generate $\rightarrow$ Self-Eval $\rightarrow$ Fallback), và trả kết quả streaming cho người dùng.
